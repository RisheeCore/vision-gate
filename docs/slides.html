Capstone

VISION

Very Intelligent System for Inspection, Optimization and Navigation

Pre-execution policy gating with a sandboxed, verified self-healing loop.

Deterministic gate · capability-dropped execution · bounded repair · measured escape rate

The problem

  • LLM output runs on the host before anyone audits it.
  • Linters read text; they do not model behaviour.
  • Reviewing every generated script by hand does not scale.

Three layers

  • Layer 1 — deterministic AST policy engine. No network, no model.
  • Layer 2 — capability-dropped Docker sandbox.
  • Layer 3 — bounded self-heal loop, fail-closed.

The key is used only for repair. Detection is never an LLM.

Layer 1 — the gate

  • 19 rule families: parse, imports, builtins, path, destructive, resources, introspection, obfuscation, shell.
  • Versioned v0–v3, each strictly stronger.
  • Line-numbered findings, sub-millisecond, fully offline.

Layer 2 — the sandbox

  • --read-only root, --cap-drop ALL, no-new-privileges
  • --pids-limit, --ulimit, tmpfs noexec,nosuid,size
  • --network none, uid 65534
  • 15 tests, including two positive controls that prove the canary fires

Layer 3 — the loop

  • code → gate → BLOCK → reflect → code
  • SHA repeat detection, max_iters budget
  • Budget exhausted → fail closed, never a silent pass

Bounded, not open-ended.

Fidelity gate

  • Healed output is re-audited; not ALLOW → 503, not a bad answer.
  • Provenance diff: preserved / dropped / invented.
  • Side-by-side in the UI so the claim is inspectable.

Limitations

  • Python only, single file. No PE/ELF, no C.
  • Obfuscation flagged, not reversed.
  • Ransomware hardened behaviourally; keys not recovered.
  • Heuristic coverage; family-level split.
  • Canary profile differs from strict profile.

Threats to validity

  • Family-level split, not file-level independence.
  • Single annotator on the corpus.
  • FPR 0/63 — cite the Wilson upper bound, not the point estimate.
  • LLM repair can hallucinate; re-audit mitigates, does not eliminate.
